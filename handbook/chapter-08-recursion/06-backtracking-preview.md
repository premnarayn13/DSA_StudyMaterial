# 06. Backtracking Preview: State Space Search Trees & The Choose-Recurse-Unchoose Triad

## 1. Introduction
**Backtracking** is a specialized algorithmic extension of recursion designed to systematically explore the **State Space Search Tree** of combinatorial decision problems (such as Subsets, Permutations, Combinations, N-Queens, and Sudoku). Unlike standard linear or Divide & Conquer recursion where subproblem inputs flow in one direction down the stack, backtracking evaluates candidate solutions incrementally, **PRUNING** invalid branches early whenever constraints are violated, and reverting state choices via the **Choose-Recurse-Unchoose Triad**.

> **Important:** The Core Invariants of Backtracking:
> 1. **State Space Search Tree**: An implicit tree structure representing all candidate configurations generated by making sequence choices at each level.
> 2. **Constraint Validation Guard (Bounding Function / Pruning)**: Checking whether the current candidate state can possibly yield a valid complete solution. If invalid, the algorithm **PRUNES** the subtree, skipping millions of hopeless sub-states!
> 3. **The Choose-Recurse-Unchoose Triad**:
>    - **CHOOSE**: Modify state by making a candidate decision (e.g., `path.add(candidate)`).
>    - **RECURSE**: Self-invoke to explore deeper decision levels (`backtrack(level + 1)`).
>    - **UNCHOOSE (Backtrack)**: Revert state change (`path.remove(path.size() - 1)`) so sibling choices start with a clean state! ⚡

```
The Choose-Recurse-Unchoose Triad Lifecycle:
+-----------------------------------------------------------------------+
| 1. CHOOSE:    path.add(candidate); mark visited[i] = true;             |
+-----------------------------------------------------------------------+
                                   │
                                   v
+-----------------------------------------------------------------------+
| 2. RECURSE:   backtrack(index + 1, path, result);                      |
+-----------------------------------------------------------------------+
                                   │
                                   v
+-----------------------------------------------------------------------+
| 3. UNCHOOSE:  path.remove(path.size() - 1); mark visited[i] = false;  |
+-----------------------------------------------------------------------+
```

## 3. Characteristics & Search Space Pruning Proof

### 3.1 Mathematical Proof of Bounding Function Efficiency
* Let $M$ be the maximum branching factor and $N$ be the tree depth. A naive exhaustive search evaluates $O(M^N)$ states.
* By applying a **Bounding Function (Constraint Guard)** at depth $k < N$, an entire subtree of size $M^{N-k}$ is pruned in $O(1)$ time.
* For example, in N-Queens ($N = 8$), naive placement evaluates $8^8 \approx 16,777,216$ states. Bounding diagonal attacks reduces evaluated states to just $15,720$ (a **99.9% reduction in search time**!). ⚡

## 4. Internal Working Mechanics: The Backtracking Execution Engine

Tracing a simple 2-element permutation generator for `[1, 2]`:

```
Init: path = [], visited = [false, false]

Level 0:
- Try i = 0 (val 1):
  - CHOOSE: path = [1], visited[0] = true.
  - RECURSE to Level 1:
    - Try i = 0 (val 1): visited[0] is true -> SKIP.
    - Try i = 1 (val 2):
      - CHOOSE: path = [1, 2], visited[1] = true.
      - RECURSE to Level 2: Base Case (path.size() == 2)! Add [1, 2] to result! Return.
      - UNCHOOSE: path = [1], visited[1] = false.
  - UNCHOOSE: path = [], visited[0] = false.

- Try i = 1 (val 2):
  - CHOOSE: path = [2], visited[1] = true.
  - RECURSE to Level 1:
    - Try i = 0 (val 1):
      - CHOOSE: path = [2, 1], visited[0] = true.
      - RECURSE to Level 2: Base Case! Add [2, 1] to result! Return.
      - UNCHOOSE: path = [2], visited[0] = false.
  - UNCHOOSE: path = [], visited[1] = false.

Final Result: [[1, 2], [2, 1]]! Clean state restored! ✅
```

## 6. Operations & Complete Java Implementation

Below is a production-grade Java suite demonstrating the Choose-Recurse-Unchoose Triad across permutation generation, subset combination search, and constraint-based grid pathfinding.

```java
import java.util.*;

/**
 * Production-Grade Suite Demonstrating Backtracking Mechanics,
 * State Space Search Trees, and the Choose-Recurse-Unchoose Triad.
 */
public class BacktrackingPreviewMaster {

    // =========================================================================
    // 1. PERMUTATIONS GENERATION (Visited Array Backtracking O(N! * N))
    // =========================================================================
    /**
     * Generates all unique permutations of an integer array.
     * Demonstrates the classic Choose-Recurse-Unchoose Triad.
     *
     * @param nums distinct integers
     * @return list of all permutations
     */
    public List<List<Integer>> generatePermutations(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        if (nums == null) return result;

        boolean[] visited = new boolean[nums.length];
        backtrackPermutations(nums, visited, new ArrayList<>(), result);
        return result;
    }

    private void backtrackPermutations(int[] nums, boolean[] visited, 
                                      List<Integer> path, List<List<Integer>> result) {
        // Base Case Guard: Complete permutation formed
        if (path.size() == nums.length) {
            result.add(new ArrayList<>(path)); // Deep copy required!
            return;
        }

        for (int i = 0; i < nums.length; i++) {
            // Constraint Bounding: Skip if element is already in current path
            if (visited[i]) continue;

            // 1. CHOOSE
            visited[i] = true;
            path.add(nums[i]);

            // 2. RECURSE
            backtrackPermutations(nums, visited, path, result);

            // 3. UNCHOOSE (Backtrack state restoration)
            path.remove(path.size() - 1);
            visited[i] = false;
        }
    }

    // =========================================================================
    // 2. COMBINATION SUM SEARCH (Constraint Pruning O(2^N))
    // =========================================================================
    /**
     * Finds all unique combinations in candidates that sum to target.
     * Demonstrates early branch pruning.
     *
     * @param candidates sorted positive integers
     * @param target sum goal
     * @return list of valid combinations
     */
    public List<List<Integer>> combinationSum(int[] candidates, int target) {
        List<List<Integer>> result = new ArrayList<>();
        if (candidates == null) return result;

        Arrays.sort(candidates); // Sort for early pruning optimization
        backtrackCombinations(candidates, target, 0, new ArrayList<>(), result);
        return result;
    }

    private void backtrackCombinations(int[] candidates, int remainingTarget, 
                                       int start, List<Integer> path, 
                                       List<List<Integer>> result) {
        // Base Case Guard
        if (remainingTarget == 0) {
            result.add(new ArrayList<>(path));
            return;
        }

        for (int i = start; i < candidates.length; i++) {
            // Pruning Guard: If current candidate exceeds remaining target, stop loop!
            if (candidates[i] > remainingTarget) {
                break; // Early pruning due to sorted array!
            }

            // 1. CHOOSE
            path.add(candidates[i]);

            // 2. RECURSE (Pass 'i' to allow element reuse, or 'i + 1' for single use)
            backtrackCombinations(candidates, remainingTarget - candidates[i], i, path, result);

            // 3. UNCHOOSE
            path.remove(path.size() - 1);
        }
    }
}
```

## 10. Edge Cases & Boundary Handling

1. **Adding Reference Without Deep Copying**:
   - Writing `result.add(path)` adds a reference to the mutable list `path`. When backtracking unwinds, `path` becomes empty `[]`, resulting in `[[], [], []]` in `result`.
   - **Fix**: ALWAYS store a deep snapshot copy: `result.add(new ArrayList<>(path))`.

2. **Forgetting to Reset Visited Flags**:
   - Omitting `visited[i] = false` during the UNCHOOSE step permanently locks index $i$, preventing sibling branches from utilizing that element.

## 11. Common Mistakes & Anti-Patterns

* **Anti-Pattern 1: Mutating Collections Inside Method Arguments**:
  ```java
  // BAD: Creating new list inline per call creates O(2^N * N) extra heap garbage!
  List<Integer> nextPath = new ArrayList<>(path);
  nextPath.add(val);
  backtrack(nextPath); 
  
  // GOOD: In-place mutation with Choose-Recurse-Unchoose!
  path.add(val);
  backtrack(path);
  path.remove(path.size() - 1); // Hygiene! ⚡
  ```

## 12. Important Notes & Architectural Rules

> **Interview Requirement:** The Fundamental Rule of Deep Copying in Backtracking:
> In backtracking algorithms, the search path list `path` is a single mutable object shared across all recursion frames.
> Whenever a base case is satisfied and a solution path is found, you MUST create a new deep copy of the path before adding it to the final result:
> `result.add(new ArrayList<>(path));`
> Failing to make a deep copy is the #1 bug candidate in backtracking interviews! ⚡

## 15. Frequently Asked Interview Questions

* **Q: What is the difference between pure recursion and backtracking?**  
  *A:* Pure recursion breaks a problem down into independent sub-instances (Divide & Conquer). Backtracking incrementally builds candidate solutions on a shared mutable state, pruning invalid search paths and explicitly undoing choices (Unchoose).

* **Q: What is a Bounding Function in backtracking?**  
  *A:* A predicate test applied at an intermediate node in the search tree that evaluates whether extending the current path can yield a valid solution. If false, the subtree is pruned instantly.
